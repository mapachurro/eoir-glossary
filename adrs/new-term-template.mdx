# New term template

*This is for the purposes of establishing which fields are minimally necessary for a new term to be added to the glossary.*

Please see [RFC 2119](https://datatracker.ietf.org/doc/html/rfc2119) for reference.

## Object structure:

```json 
  {
    "english": "212C waiver",
    "englishDefinition": "",
    "spanish": "exoneración conforme con la 212C",
    "spanishDefinition": "",
    "comments": "",
    "category": [],
    "tags": [],
    "aliases": [],
    "status": "active",
    "lastUpdated": "",
    "source": "Refactor_ EOIR Spanish-English Glossary 2020.xlsx - 2020 Terms List.csv",
    "proposals": "",
    "id": "212c-waiver-exoneracion-conforme-con-la-212c",
    "contrastsWith": []
  },
  ```

  ## Obligatory minimal fields:

  A new term MUST have EITHER 

  - `"english"`
  OR
  - `"spanish"`

  with a value, as seen above in the example.

  Additionally, a new term MUST have:

  - `"source"`.

  The `"id"` field, additionally, is REQUIRED for functionality. 

  However, upon inclusion of a new term, the `id` will be automatically generated by the build process.
  Therefore, you MUST NOT add your own ID.

*Ideally, a term SHOULD be submitted with both English and Spanish versions, but the real world is far from ideal.
It's better to submit a term without an equivalent than none at all.
**If the term being submitted does not have both, mark the `status` field as `in progress`:***

`"status": "in progress",`

## Clean object template e.g. for a PR:

```json 
  {
    "english": "",
    "englishDefinition": "",
    "spanish": "",
    "spanishDefinition": "",
    "comments": "",
    "category": [],
    "tags": [],
    "aliases": [],
    "status": "active / in progress",
    "lastUpdated": "",
    "source": "",
    "proposals": "",
    "id": "",
    "contrastsWith": []
  },
  ```
